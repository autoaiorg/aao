## Implementation and acceptance status

RA-01/RA-02 controls and mapped negative tests have been added in this candidate. Their status is `implemented-unverified`, not PASS: the tests have not yet been run on the final candidate SHA, an independent Antigravity audit is pending, and the CEO must regenerate and verify the trust root with the new registry fields. Existing installed trust roots do not carry these fields and must not be used as evidence. No RA status is upgraded by this change.

The runtime authorization issuer refuses every protected-route classification above R1. The integrator rejects route-copy digest divergence and required checks without an authorized publishing App. The supervisor records implementer identities only from exact registry-mapped push principals; PR authors and unknown push principals do not resolve attribution.

## Evidence limits

- Unit tests use local repositories and existing fakes only; none establishes GitHub's live ruleset behavior or effective credential/protection configuration.
- The working tree’s policy itself labels RA-01 through RA-09 requirements as pending. This traceability document does not upgrade their state.
- No cases are marked PASS. An audited run must record exact source SHA, test command/output, relevant configuration, and independent auditor disposition before any acceptance claim.
